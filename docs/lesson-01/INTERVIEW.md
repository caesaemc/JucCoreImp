# 第一课面试复盘

回答时建议使用：

```text
结论 → 原理 → 规范保证 → 反例或边界 → 工程做法
```

## 1. 并发和并行有什么区别？

参考要点：

- 并发表示多个任务在重叠时间内推进，关注任务协调。
- 并行表示多个任务在同一时刻执行，关注计算资源利用。
- 单核可以并发但难以真正并行。

## 2. 什么是竞态条件？什么是数据竞争？

参考要点：

- 竞态条件：结果依赖线程相对时序，某些时序破坏业务正确性。
- 数据竞争：两个未被 happens-before 排序的冲突访问，且至少一个是写。
- 两者相关但不是同义词。

## 3. 为什么 `i++` 不是线程安全的？

参考要点：

- 它包含读取、计算、写回。
- 多线程可能读取同一个旧值。
- 单次 `int` 读写的原子性不能扩展到复合操作。

## 4. 原子性、可见性、有序性分别是什么？

参考要点：

- 原子性：操作是否不可分割。
- 可见性：一个线程的写是否保证被另一个线程观察到。
- 有序性：跨线程观察时，操作是否具有所需的先后约束。

## 5. happens-before 是物理时间顺序吗？

参考要点：

- 不是简单的墙上时钟顺序。
- 它是 JMM 中的内存可见性和顺序关系。
- 实现可以重排，只要外部行为仍符合 happens-before 约束。

## 6. `Thread.start()` 有什么内存语义？

参考要点：

- 调用线程在 `start()` 之前的动作 happens-before 被启动线程中的动作。
- 可以用它向新线程安全发布启动前准备的数据。

## 7. `Thread.join()` 有什么内存语义？

参考要点：

- 目标线程中的所有动作 happens-before 其他线程从它的 `join()` 成功返回。
- 因此 join 后可以观察目标线程结束前的普通字段写入。

## 8. `Thread.sleep()` 能保证看到其他线程的新值吗？

参考要点：

- 不能。
- sleep 和 yield 不具有内存同步语义。
- 看似有效只是调度或当前实现造成的偶然现象。

## 9. 没有 happens-before 是否意味着一定读取旧值？

参考要点：

- 不意味着一定读取旧值。
- 意味着程序没有所需的规范保证。
- 一次或多次运行读取到新值不能证明正确。

## 10. 如何测试一个存在竞态的程序？

参考要点：

- 用锁存器或屏障扩大并控制竞争窗口。
- 把复合操作拆开，构造确定性错误时序。
- 压力测试用于发现问题，不用于单独证明正确。
- 正确性最终需要规范推理，复杂算法可使用 jcstress 等工具。

## 代码分析题

```java
class Holder {
    int value;
}

Holder holder = new Holder();
holder.value = 42;

Thread thread = new Thread(() -> System.out.println(holder.value));
thread.start();
```

问题：工作线程是否保证打印 42？

参考答案：保证。主线程对 `value` 的写在 `start()` 之前，依据 start 规则，该写 happens-before 新线程中的读取。

## 生产场景题

某服务用普通 `int` 字段统计请求数。压测发现统计值偶尔小于日志中的请求总数，但 CPU、内存和网络均正常。如何分析？

参考思路：

1. 检查是否有多个线程执行 `count++`。
2. 将操作拆成读取、计算、写回，说明丢失更新。
3. 确认读取统计值的位置是否也具有可见性保证。
4. 根据需求选择锁或原子计数方案。
5. 如果只需要高吞吐近实时统计，可进一步评估 LongAdder；它将在第四课学习。
