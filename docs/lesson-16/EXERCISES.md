# 第 16 课练习与最终验收

## 必做 1：降级决策

完成 `DegradationPolicyExercise.decide`：

- 全部成功 → `OK`
- 仅非关键调用非成功 → `PARTIAL`
- 任一关键调用非成功 → `FAILED`

移除 `DegradationPolicyExerciseTest` 上的 `@Disabled` 并运行。

## 必做 2：容量设计

假设：

- 峰值入口 1,000 RPS。
- 每请求调用库存、价格、优惠、推荐。
- 总 deadline 200 ms。
- 数据库连接池 80。
- 推荐服务额度 300 并发。

提交一份容量方案，至少说明：

1. 入口最大在途数。
2. 每个 Bulkhead 容量，而不是所有下游共用一个值。
3. 平台版 worker/queue 或选择虚拟线程的理由。
4. 满载拒绝如何映射到接口协议。
5. 用 Little's Law 做的初始估算及压测校准方法。

## 必做 3：故障注入

分别注入：

- 一个非关键下游持续失败。
- 一个关键下游 P99 超过总 deadline。
- 底层调用忽略中断。
- 平台队列饱和。
- 服务关闭时仍有请求执行。

为每类记录结果协议、指标变化、线程是否泄漏及期望告警。

## 必做 4：平台与虚拟线程对比

使用相同调用工厂、相同资源许可与相同机器：

- 逐步增加并发请求。
- 记录吞吐、P50、P95、P99、拒绝/超时和 CPU。
- 录制 JFR。
- 解释拐点来自执行载体、资源许可、下游还是入口。
