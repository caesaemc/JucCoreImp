# 第 05 课面试复盘

## 1. AQS 是什么？

用于构建锁和同步器的框架。子类定义 state 的获取释放规则，AQS 管理等待队列、阻塞、唤醒、中断和取消。

## 2. AQS 的 state 固定表示锁次数吗？

不是。含义由子类决定，可以是重入次数、剩余许可或剩余计数。

## 3. AQS 队列是什么？

一种基于 CLH 思想改造的 FIFO 同步等待队列。节点记录线程和等待状态，线程在条件不满足时 park。

## 4. 公平锁一定公平吗？

它按照等待顺序减少插队，但线程调度仍由 JVM 和操作系统决定；tryLock 等路径也可能有不同语义。

## 5. Condition 与 Object.wait 有何关系？

两者都用于条件等待。Condition 与显式 Lock 配合，一把锁可创建多个条件队列，并提供可中断、超时等更清晰的 API。

## 6. signal 后线程立刻运行吗？

不会。它先从条件队列转移到同步队列，重新获得锁后 await 才返回。

## 7. 为什么锁必须在 finally 中释放？

临界区异常也必须释放，否则其他线程可能永久阻塞。

## 场景题

生产消费缓冲区为什么适合两个 Condition？

生产者只等待 `notFull`，消费者只等待 `notEmpty`；状态变化时精确唤醒对应类型，减少无效竞争，同时 while 重新检查条件保证正确性。
