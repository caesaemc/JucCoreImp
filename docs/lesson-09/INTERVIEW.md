# 第 09 课面试复盘

## ThreadPoolExecutor 提交任务顺序？

先尝试核心线程，再尝试入队，队列失败后再创建到最大线程数，最后拒绝。

## 为什么不是先创建到最大再入队？

线程池以 core 作为常态线程规模，队列吸收波动；只有队列无法接受时才扩展到 max。不同队列会改变这一策略的实际表现。

## ctl 是什么？

一个原子字段同时编码线程池运行状态和 worker 数量，使相关状态转换可以原子协调。

## execute 与 submit 的异常表现？

execute 的未捕获异常通常到达工作线程的异常处理；submit 把任务包装为 FutureTask，异常存入 Future，需要通过 get 或 afterExecute 检查。

## CallerRunsPolicy 的意义？

由提交线程执行被拒任务，降低提交速度形成反压。但会占用调用线程，必须评估事件循环、请求线程和递归提交风险。

## 如何设置线程数？

公式只能作为起点。需要根据 CPU/阻塞比例、下游容量、任务时延、队列等待和压测结果调整，并进行线程池隔离。

## 场景题

线程池 active 始终等于 max，队列满且拒绝增加：

- 确认是流量突发还是任务变慢。
- 分解排队时间与执行时间。
- 检查下游依赖、锁等待和 GC。
- 先保护系统：限流、拒绝、降级。
- 不盲目增加线程，因为瓶颈可能是下游或锁。
