# JUC 学习档案

这里保存个人学习过程，不替代各课已有的讲义、练习和面试题。

- `docs/lesson-XX/`：课程的标准教学内容。
- `docs/learning-journal/lesson-XX.md`：实际学习过程、问题、实验和复盘。
- 交互网页：即时勾选进度，保存在浏览器本地。
- Git 学习档案：长期保留结论、证据和认知变化。

## 使用方式

每一课只维护一份主档案，学习时按以下流程更新：

1. 开始课程时，写入知识小结、正确学习路径和当前任务。
2. 完成一个网页 Todo 后，同步勾选课程档案中的对应条目。
3. 运行代码后，记录命令、预期结果、实际结果和原因分析。
4. 讨论中出现有价值的问题时，追加到“有价值问答”。
5. 修改练习代码后，记录实现选择、测试证据和正确性证明。
6. 完成课程时，填写课后复盘和 D+1、D+7、D+30 回顾计划。

## 什么问题值得记录

符合任意一条就记录：

- 修正了一个错误理解或常见误区。
- 解释了一个 API、JMM 规则或实现机制的边界。
- 能转化为面试问题或生产故障分析方法。
- 影响代码设计、性能、可靠性或技术选型。
- 实验结果与原先预测不同。
- 可以迁移到其他并发场景。

以下内容默认不记录：

- 单纯的页面导航和重复确认。
- 不影响理解的环境操作细节。
- 已经完整记录、没有新增结论的重复问题。

用户可以随时指定“这条记下来”或“这条不要记录”。

## 问答记录格式

每条有价值问答至少包含：

```text
问题
当时的理解
最终结论
为什么
源码或实验依据
适用边界
面试表达
待继续验证的问题
```

## 状态定义

- `未开始`：尚未进入该课。
- `进行中`：至少开始一个学习任务，但还未满足课程完成标准。
- `待复盘`：代码和测试完成，面试口述或总结尚未通过。
- `已完成`：Todo、实验、练习、面试复盘全部完成。
- `需重学`：D+1、D+7 或 D+30 回顾未达到掌握标准。
