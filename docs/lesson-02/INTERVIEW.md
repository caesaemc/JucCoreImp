# 第 02 课面试复盘

## 1. volatile 能保证原子性吗？

只能保证单次 volatile 读写的相关语义，不能让 `++` 或 check-then-act 变成原子操作。

## 2. volatile 和 synchronized 的主要差别？

- volatile 不提供互斥，适合独立状态发布。
- synchronized 同时提供互斥和监视器内存语义。
- 多字段不变量通常需要锁或不可变快照。

## 3. synchronized 锁的是什么？

锁的是对象监视器。实例同步方法锁 `this`，静态同步方法锁对应 `Class` 对象，同步块锁显式表达式得到的对象。

## 4. 什么是安全发布？

让其他线程不仅看到对象引用，还保证看到构造完成的合法状态。可通过静态初始化、volatile、锁、并发容器等实现。

## 5. final 字段一定线程安全吗？

不是。final 提供初始化安全性，但对象内部引用的可变对象仍可变化，而且构造期间 `this` 逸出会破坏前提。

## 6. DCL 为什么需要 volatile？

它负责安全发布实例，并禁止其他线程观察到“引用已赋值但构造效果尚不可见”的状态。

## 场景题

读取频率极高的路由配置包含多个相关字段，如何无锁读取？

参考答案：把配置建模为不可变对象，更新线程完整构造新实例后通过 volatile 引用一次性发布；读取者获取一次引用并在该快照上完成全部操作。
